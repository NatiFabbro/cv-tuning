# Guía de formato y palabras clave para ATS

Un ATS (sistema que filtra postulaciones) lee el CV como texto. Si el formato es raro, puede leerlo mal. Estas reglas valen para todas las plantillas.

## Formato

- **Una columna.** Sin tablas, sin cuadros de texto, sin columnas ni gráficos para organizar el contenido.
- **Sin información en encabezado ni pie de página** (algunos ATS no los leen). Nombre y contacto van en el cuerpo.
- **Sin imágenes** ni íconos. Sin barras o estrellas para mostrar nivel de skills: usá texto ("Inglés: B2").
- **Fuentes estándar** (Arial en las plantillas del plugin). Tamaño 10–12 pt para el texto.
- **Viñetas reales** de lista, no caracteres sueltos.
- **Fechas consistentes** en todo el documento (ver `locales.md`).
- **Títulos de sección estándar** (ver `locales.md`): "Experiencia", no "Mi recorrido".
- **Entrega en DOCX y PDF** con texto seleccionable (no una imagen del CV).
- Orden cronológico inverso en experiencia y educación.

## Palabras clave

- Las palabras clave salen del posting: herramientas, tecnologías, metodologías, títulos, certificaciones, verbos del rol.
- Usá el **término exacto** del posting cuando el perfil respalda el hecho (sigla y forma completa una vez cada una: "Search Engine Optimization (SEO)").
- Ponelas donde ya cabrían naturalmente: resumen, logros, skills. No hagas listas de keywords sueltas ni texto oculto (blanco sobre blanco): los ATS modernos lo detectan y un reclutador lo lee como trampa.
- Nunca agregues una palabra clave que el perfil no respalde (ver `honesty-rules.md`).

## Longitud y contenido

Cuántas páginas, cómo recortar, cómo se escribe cada sección y cada logro está en `cv-structure.md`. Desde el punto de vista ATS, lo que importa es no achicar tipografía ni márgenes para que entre el contenido: se recorta contenido.
